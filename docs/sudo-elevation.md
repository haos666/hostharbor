# sudo 提权凭证

服务器编辑页可启用 sudo，并选择密码来源：

- 与登录凭证共用密码：登录必须绑定密码类型；SSH Key 的口令不是 sudo 密码。
- 绑定独立密码凭证：从凭证库的密码分类中选择。密码仍由凭证页维护，不在服务器页重复输入。
- 服务器已配置 sudo 免密：以非交互方式请求；不满足免密条件就失败，不等待输入。

旧服务器默认不启用。启用配置不会修改远端 sudoers，不改变普通命令、AI 调查或 SFTP 的执行身份。更改绑定或密码会作废旧审批并请求中断已有连接；已派发操作不能据此断言远端进程停止。

## 智能体调用

`list_servers` 返回 `sudoConfigured` 布尔值。明确需要提权时，调用 `start_command`，提供 `elevation: "sudo"`，`command` 填写不带 sudo 前缀的整条命令；整条命令以 root 执行，目录在提权后进入。审批中心和历史显示执行身份，密码不出现在命令或 MCP 输入中。

兼容一个普通字面命令的 `sudo <command>` / `sudo -u root <command>`，解析后显示提权身份与实际命令。对 `sudo <command>; <other-command>`、管道、其他目标账号或 sudo 特殊选项不猜测作用范围，提示改用结构化参数。命令中的其他交互提示不会自动得到密码。不要让智能体提交 `echo <password> | sudo`，也不要在返回错误后自动重提。

提权遵循当前模式：宽松审批对日常运维自动通过，明确破坏性动作仍人工；其他模式保留人工批准。显式拒绝/暂停策略优先，绑定凭证版本和派发前复查不变。权限、审批有效期、目标与凭证版本、主机指纹、持久化意图仍统一检查，不能只凭客户端声称“已批准”发送密码。文件传输不提权。

## 认证与边界

执行器使用固定 `/usr/bin/sudo -k -S -p <fresh-prompt> -u root -- /bin/sh -c <approved-wrapper>`；免密使用 `-k -n`。内层 Shell 首先关闭标准输入，再执行工作目录确认和命令，避免认证输入流进入目标命令。不会开启 PTY、修改 sudoers、关闭主机验证或启动持久 root 会话。

密码只在 SSH stderr 收到本操作的随机提示时，通过通道标准输入发送一次，随后关闭输入。提示按字节跨块处理，并在进入录制前移除；密码与其回显使用既有跨块脱敏，内存 Buffer 尽快清理。JavaScript/SSH 库的内存副本不能保证全部擦除；已认证远端的 sudo/PAM 仍是信任对象。

15秒未完成认证即断开，不进行密码重试。认证失败、sudoers 不允许、需要终端、MFA 或 PAM 不接受自定义提示时提示检查配置；没有收到确定结束结果时仍记录结果未知。不会为“修复提权”自动重试命令。退出码125的目录失败单独报告。

首版只支持 root 和非交互命令；sudoers 必须允许所请求的 `/bin/sh -c` 包装命令。不把绑定密码当成已获得服务器授权，也不绕过仅允许指定可执行文件的 sudoers 限制。要求 root/目标账号密码的 sudoers 策略应绑定对应独立密码，复用登录密码仅适合要求登录账号密码的策略。

协议依据：[sudo 项目手册](https://github.com/sudo-project/sudo/blob/main/docs/sudo.man.in)。
