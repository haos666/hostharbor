# 个人工作流：加密备份、SSH 配置导入与服务器常用操作

创建日期：2026-10-26（Asia/Shanghai）。

状态：**P1 加密备份与恢复已在本地实现并验证，尚未发布；P2/P3 待实施。** 本计划取代同类研究报告中 R1–R3 的“首批实施建议”；研究保留作参考，暂不增加审批选项、活动预算或多用户功能。

## 1. 顺序与交付范围

| 阶段 | 功能 | 用户得到什么 |
| --- | --- | --- |
| P1 | 加密备份与导入备份 | 将自己的服务器、凭证和维护资料打包，换机或重装后可以恢复 |
| P2 | 导入已有 SSH 配置 | 预览已有主机及连接关系，选择后批量添加，减少手工录入 |
| P3 | 每台服务器的常用操作 | 保存该服务器的常用命令，人可以点击执行，智能体可以发现并调用 |

三个阶段保持同一资产/凭证引用模型，按阶段验收。开发与测试以合成资产为准，不读取或导出用户现有凭证，不执行真实服务器操作。先完成本地实现与验证，按既有大版本节奏集中推送 GitHub。

## 2. 当前代码约束

- SQLite 当前 schema 为 v13；凭证、服务器、主机指纹、档案和应用分别保存。服务器会引用登录、SOCKS5 和 sudo 凭证，也会引用跳板服务器。
- 凭证主密钥经 Main 的 OS 保护；Core 用该密钥及派生密钥加密不同记录。复制数据库和 `protected-key` 文件不是可移植备份。
- 桌面锁定与后台 MCP 继续执行可分开。导出/导入必须要求桌面明确解锁，不能因为后台仍持钥就允许敏感桌面操作。
- 当前只支持一层、直连的 SSH 跳板；配置导入不能静默扁平化多跳路由。
- 所有执行仍进入 OperationService，保留审批、幂等、授权/配置重检、录制和未知结果规则。

主要实现位置：`src/main/key-store.ts`、`src/core/security/`、`src/core/credentials/crypto.ts`、`src/core/storage/database.ts`、`src/core/servers/service.ts`、`src/core/operations/service.ts`、`src/shared/contracts.ts`。

## 3. P1：加密备份与导入备份

### 3.1 用户入口与流程

设置 → 数据与集成 → **备份与恢复**，首版保留两个主要动作：

1. **创建加密备份**：显示备份内容和数量 → 输入并确认备份密码 → 选择保存位置 → 创建成功。
2. **导入备份**：选择备份文件 → 输入备份密码 → 显示内容/冲突预览 → 确认导入 → 显示新增、跳过和待处理结果。

备份密码独立于应用加锁密码，只要求非空、两次一致，不加最小长度、特殊字符或复杂度要求。不自动填入已知密码，不将备份密码记住或发送给 AI。说明“请妥善保管，应用安全码不能解密这个备份”。

新电脑先完成本机密码和安全码设置，再导入；使用新电脑自己的主密钥重新加密。原电脑的解锁密码、安全码和 OS 保护文件不迁移。已有安装导入后仍保留自己的解锁方式。

### 3.2 首版备份内容

首版明确是**资产与维护资料备份**，不是整台电脑或完整活动历史镜像。

| 数据 | 首版处理 |
| --- | --- |
| 密码、私钥、私钥口令 | 包含，始终处于备份整体加密内 |
| 服务器及登录/提权/代理绑定 | 包含，保持引用关系 |
| 主机指纹记录 | 包含；导入遇到本机已有不同指纹时报告冲突，不自动替换 |
| 已完成服务器档案、人工修正、应用索引与日志入口 | 包含；不带正在运行的调查和原始命令采集输出 |
| 文件设置 | 包含远端目录、大小/校验/超时配置；不含本地暂存文件 |
| 服务器常用操作 | P3 完成后纳入同一备份 schema；旧备份缺省为空，做兼容测试 |
| MCP 接入、Token、已批准授权和短期状态 | 不导出，不在恢复后自动授予智能体访问权 |
| 操作历史、回放、传输文件、临时文件 | 不包含；界面提前说明，避免误以为日志已备份 |
| 应用加锁密码、安全码、OS 包装密钥 | 不包含 |
| AI API Key、全局审批/通知/语言设置 | 首版不包含；优先保证核心资产跨机恢复，避免多处配置半恢复及隐式改变当前审批策略 |

首版不做云同步、自动定时备份或恢复后自动连接服务器。

### 3.3 数据包与代码架构

- 新增 Core `backup` 模块，拆分 envelope、portable schema、导出快照、导入预览/提交。只复用成熟加密原语和本项目既有模式，不自行设计密码算法。
- 采用带 magic/version 的 `.hhbackup` 数据包；外层只留解密必需的有限格式信息，资产名、地址、数量、档案和凭证均在加密载荷内。
- 使用独立随机 salt、随机 nonce、scrypt 派生与 AES-256-GCM 认证加密，绑定格式版本和必要头部。KDF 使用固定且有界的参数档位；先在目标 Mac 测量，不允许文件随意指定巨大资源开销。
- 初版使用有界、版本化 JSON 载荷，不做 ZIP 解包或任意路径还原。文件大小、记录数量、文本字段、头部参数在分配内存和解密前后分别验证。
- 导出是逻辑记录快照，在 Core 内部解密并立即进入备份加密链路；明文不写临时文件、不进 Renderer、不写日志。缓冲区尽力清零，不声称绝对擦除 JS 内存。
- Main 管理原生文件对话框和桌面解锁门禁；Core 管理数据与密码学。Renderer 仅短暂持有密码输入、计数和脱敏预览，不收到整个解密载荷。
- 预览与提交使用一次性导入会话 ID，绑定文件摘要、解锁会话和当前资产版本；关闭、锁定、超时或提交后释放材料。修改原文件后不能提交旧预览。
- 写出的临时文件也只有密文，权限尽量限制为当前用户；写完后再发布最终文件。覆盖已有文件通过正常保存对话框确认。
- 备份和恢复仅有固定桌面 IPC，不向 MCP 暴露导出凭证或批量写资产能力。

### 3.4 首版导入策略：保留已有数据，预览后新增

不做“清空并覆盖本机”。同机误导入也应可预测。

- 对备份记录重新分配本机 ID，建立 old→new 映射，统一重建凭证、服务器、跳板、提权、应用、日志入口和常用操作引用；不能直接复制带旧 AAD 的密文。
- 可复用的现有数据必须完整匹配并经过预览确认。不能只因为名称或 host 相同就覆盖/合并服务器或凭证；私钥/密码匹配不在预览中暴露明文或可离线比较的指纹。
- 默认跳过已确定重复的条目；同名但连接/凭证不同的条目标为冲突，可选择跳过或作为新条目保留。备份内部依赖缺失、非法跳板链或指纹冲突不能悄悄降级成直连。
- 一台服务器的依赖被跳过时，联动显示该服务器不能导入及原因；不能写入悬空引用。档案/应用的来源与修正标记保持，重建导入后的版本关联。
- 导入前如有待审批或运行中操作、连接/目录浏览或调查，提示待完成/取消后再导入；提交前重检，检查至同步事务结束之间不让出 Core 事件循环。预览阶段不修改数据库。
- 校验后在单一数据库事务中提交，失败全部回滚；恢复原有执行接入状态，不自动重跑任务、不自动新增 MCP 授权。
- 不导入 Token 与审批策略意味着现有接入和政策保持本机设置；新服务器须另行授权给智能体。

### 3.5 验收

本地验收结果：18 项备份专项测试、全量 888 项测试、类型与生产构建通过。macOS arm64 的独立 OS 密钥、Utility IPC 和恢复后合成 SSH 连接通过；真实 Renderer→Preload→Main→Core 的中英文导出/恢复通过，原生文件面板结果通过适配器注入。下面保留完整跨平台验收目标，尚未逐项完成的部分包括真实文件面板覆盖确认、磁盘写满、私钥认证的原生连接及 Intel/Windows 回归。

- [ ] 备份后用另一份主密钥、全新数据目录恢复，密码/私钥可用于合成 SSH fixture；跳板/代理/sudo 引用正确。
- [ ] 本机已有资产、重复导入、名称冲突、引用缺失、主机指纹冲突有稳定结果。
- [ ] 错误密码、密文/头部篡改、截断、未知版本、巨大 KDF 参数/载荷均不落入部分导入。
- [ ] 预览后换文件、资产变更、锁定、Core 重启、会话到期不能提交旧预览。
- [ ] 中途事务失败保留原数据；导出磁盘写满、取消、覆盖处理有可理解反馈。
- [ ] 未发现明文临时包、密码/私钥日志、Renderer 全量载荷或恢复后自动有效的 MCP Token。
- [ ] 中英文、进度/忙碌状态、密码显隐/确认、键盘操作及真实 macOS 文件对话框验收。

## 4. P2：导入已有 SSH 配置

### 4.1 用户流程

服务器页面“添加服务器”旁提供 **导入 SSH 配置**。选取文件（默认定位用户自己的 SSH 配置位置）→ 展示候选表格 → 勾选主机 → 选择/导入凭证并解决警告 → 导入结果。

预览列：选择、别名、地址、端口、账号、认证状态、跳板、重复/兼容性状态。详细来源与未支持配置在行详情展开，不把完整配置塞进表格。取消没有任何写入，导入不测试连接、不发网络请求、不改原配置文件。

### 4.2 首版支持与明确边界

| 内容 | 处理 |
| --- | --- |
| 具体 `Host` 别名、`HostName`、`User`、`Port` | 生成候选，保留 Host 别名作名称；缺少账号标为待补，不猜 root |
| 同一 Host 行多个具体别名 | 分别预览，识别相同连接但不擅自合并 |
| `Host *` / 模式与排除项 | 只给已枚举的具体别名提供受支持默认值；不能枚举成无限主机 |
| `IdentityFile` | 首先显示路径提示；用户明确选择后读取私钥，或绑定已有凭证；多个候选需选择，不暗中取第一个 |
| 私钥口令 | 使用现有凭证录入/校验流程，口令不出 Core 必需路径；不向智能体索取 |
| 一层 `ProxyJump` | 解析别名或明确的 user/host/port，预览依赖的跳板服务器并一并勾选/映射；依赖未满足时不作为可用连接导入 |
| 多层跳板、SSH Agent、证书、硬件 Key | 标注当前未支持/需手动处理，不宣称已导入完整认证能力 |
| `Include` | 按用户配置的 OpenSSH 路径/顺序语义解析受支持内容；展示将读取的文件，限制数量/体积/深度并检测循环；不能按“当前文件目录”随意猜相对路径 |
| `Match`、`ProxyCommand`、`LocalCommand`、`RemoteCommand` 等 | 不执行命令；可能影响连接语义时阻止该候选一键导入，提供手动处理说明，不静默忽略成可用连接 |
| 特殊 token/环境变量、系统级配置 | 只实现明确支持的展开；其余警告，不默认扫描或执行系统配置 |

配置解析遵循“首次取得的值优先”，不能用普通对象不断覆盖产生相反结果；IdentityFile 等可累积项单独处理。参考：[OpenSSH ssh_config](https://man.openbsd.org/ssh_config)。不通过 `ssh -G` 加载未经筛查的配置，因为相关配置可能含执行条件。

### 4.3 实现与验收

- Core 新增纯 parser / resolver / import-plan，文件读取适配器与纯解析分开；Main 承担用户文件选择，Renderer 不自行读私钥。
- 样例只使用 `fixture-host-a`、`fixture-jump` 等合成名称。支持大小写关键字、引号、空白、注释、等号、重复 Host、默认块顺序、模式排除及累积 IdentityFile。
- 与 P1 共用资产预览、ID 映射、重复处理和事务提交基础，但不把未经备份解密验证的配置当成可信凭证包。
- 导入私钥后保存内容的加密副本，不把原私钥路径当作“已备份凭证”；取消、锁定与失效会话清理输入。
- [ ] 纯解析及重叠规则 fixture 通过，未执行本机脚本。
- [ ] Include 循环/越界读取、多密钥、无用户名、缺跳板、重复目标与不支持参数均有明确预览。
- [ ] 文件在预览后变更时重做计划；数据库提交失败不留下半个跳板关系。
- [ ] 导入服务器仍经过首次主机身份确认，未自动读取/信任任意 known_hosts；未自动授予 MCP 接入。
- [ ] 导入后的资产可被 P1 备份，再恢复到新的合成数据目录。

## 5. P3：每台服务器的常用操作

### 5.1 个人使用方式

服务器详情增加 **常用操作**，每台服务器独立管理，不先做跨服务器脚本市场或多机批量执行。

例如某台合成服务器可保存“查看应用状态”“最近错误日志”“重启应用”。用户通过简要列表新增、编辑、删除和执行；执行后进入已有操作详情，结果留在现有操作日志。可从一条已结束命令的详情创建草稿，确认后保存，不自动收藏失败/未知操作。

首版字段：名称、可选说明、原始命令、绝对工作目录、超时、是否使用该服务器绑定的 sudo；保存 ID、revision、serverId、创建/更新时间。命令默认加密存储，不另建凭证输入；提示密码/Token 应使用凭证绑定。

**首版不做任意变量模板。** 先完成固定命令的可靠保存与调用，避免自由拼接参数造成引用、转义和审批范围问题。

### 5.2 UI 与 MCP 共用执行

- Core 新增 ServerActionService 和独立表；记录带 schemaVersion、serverId 和 revision，随服务器删除按关系清理。
- UI 先看实际命令/目录与提权方式，再执行；不把收藏直接当免审批授权。
- MCP 新增 `list_server_actions(serverId)`、`run_server_action(serverId, actionId, revision, requestKey)`；先确认目标机器，再列它的操作，不能枚举未授权主机。
- 执行时由服务端读取并冻结保存的命令，不允许 MCP 同时传入替换命令或改 serverId。动作版本、服务器配置和凭证改变后重检；等审批期间动作被编辑/删除则旧请求不能继续派发。
- OperationService 新增动作来源上下文，保留操作名称/版本与执行快照；客户端仍查询同一个 operation ID，不新增等待协议。
- MCP 不提供创建/编辑/删除常用操作接口；首版由用户在桌面维护。
- 备份支持 actions 集合及恢复 ID/版本映射；旧备份无 actions 时正常恢复为空。

### 5.3 验收

- [ ] 多服务器同名操作不串机；越权访问、伪造 serverId/actionId、过期 revision 被拒绝。
- [ ] 名称不是权限依据；编辑/删除与审批并发时不能执行过期动作。
- [ ] 固定命令、cwd、超时、sudo 走现有规则和凭证；保存或列表操作不执行 SSH。
- [ ] 幂等与未知结果规则保持，不能点击“常用操作”自动重跑未知请求。
- [ ] 备份/恢复后动作绑定正确，原日志仍能解释实际执行快照。
- [ ] 中文/英文长名称、列表空态、键盘与详情交互完整。
