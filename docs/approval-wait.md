# 审批等待与原操作续接

MCP提交命令立即返回Operation及操作ID，不把网络请求挂到审批结束。start_command、query_application_logs及get_operation返回动态agentGuidance，read_output也携带相同阶段指引，避免改用输出查询绕过等待预算。

## 两个期限

- 智能体等待预算：从原提交时间起最多三分钟。立即告知用户需要前往HostHarbor → 审批中心确认，然后按建议间隔查询。
- 审批有效期：仍是原提交后五分钟；接入授权到期可能更早。锁定、撤销、修改策略/配置等原有中止行为继续生效。

三分钟截止不会自动拒绝或取消操作，不修改已有授权。用户在三至五分钟之间批准，仍可能执行并保存结果；智能体之后读取原操作即可，不需要重新执行。已进入排队/连接/执行的操作不适用三分钟待审批预算，继续按执行状态与原时限跟进。

## 返回字段

agentGuidance为动态派生内容，不写入审批决策、加密详情或数据库，不作为新的执行授权：

| 字段 | 含义 |
| --- | --- |
| operationId | 原操作ID |
| serverTime | 当前Core时间，Unix毫秒；用它计算剩余时间 |
| nextAction | poll、ask_user、read_output、stop或inspect |
| pollAfterMs | 建议查询间隔；待审批通常10秒，交还用户时为null |
| approvalWaitUntil | 原提交后三分钟或更早授权截止，Unix毫秒；非待审批为null |
| approvalExpiresAt | 原提交后五分钟或更早授权截止，Unix毫秒；非待审批为null |
| resume | get_operation及原ID参数，用于用户要求继续后的单次查询 |
| automaticResubmitAllowed | 固定false；不能更换requestKey自动重提 |
| message | 当前阶段提示与参考话术 |

三分钟截止仍待审批时nextAction=ask_user，pollAfterMs=null。智能体应停止所有自动轮询并说明：

> 此操作仍在等待审批，尚未执行。请前往 HostHarbor → 审批中心处理；处理后回复“继续”，我会查询原操作的状态和结果。

客户端无法定时等待时直接交还用户，不能连续调用工具或执行远程sleep。重连、重新查询、重复提交原请求或AI仍在分析，都不重置截止。重复提交返回原操作的最新状态及指引，也会应用原有过期处理。

用户回复继续后，仅先查询原ID一次。仍待审批则提醒并停止，不再开启新的三分钟轮询；已批准继续读结果；拒绝、过期或未派发中止则告知未执行。重新发起失效操作需要用户重新明确确认，不能把“继续”当作新执行授权。unknown及有执行意图的中断必须如实说明结果不确定，不自动重试。

锁定、权限错误或认证失败时停止等待并提示用户处理，不通过新请求绕过。完成后读输出，当前游标无更多保留输出时返回stop；缺失或已清理的输出不授权重新执行补录。

## 能力边界与验证

现有工具名称、输入和原返回字段保持，新增可选agentGuidance。instructions、工具描述与桌面目录同步这些规则。没有新增等待工具、阻塞长连接、后台唤醒、任务记忆或跨客户端自动恢复。停止轮询仍依赖智能体遵循协议提示，客户端须保留原ID；不声称所有外部模型都会遵守或自动恢复推理。

测试覆盖精确三分钟边界、更早授权到期、重复请求不续期、过期/拒绝/中止/未知结果、已批准执行及读完停止。实际SDK和macOS utility Core/MCP使用临时合成资产与回环服务验证，三分钟通过模拟请求年龄验证，不实际等待三分钟，也未调用用户真实AI或服务器。
