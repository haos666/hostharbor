# 审批提醒与系统通知

有新的等待审批请求时，HostHarbor 提供应用内提醒、图标角标以及系统通知。它们只引导查看，不批准、拒绝或执行命令。

## 使用

「系统设置 → 通知」提供待审批角标、系统通知、提示音开关和「发送测试通知」。默认角标及系统通知开启，声音关闭。修改后点击保存；测试通知使用已保存的声音设置，测试本身不要求打开自动系统通知开关。通知设置可以在凭证库锁定时修改，不改变审批策略。

- macOS Dock 显示待审批数量；菜单栏图标旁也显示数量，菜单提供「审批中心」入口。
- Windows 任务栏使用红色提醒覆盖图标，悬浮说明和托盘菜单显示具体数量；不将覆盖图标描述成原生数字角标。
- 应用在前台时显示应用内提示；后台时按系统通知开关发送系统提醒。应用内与侧栏计数不受系统通知开关影响。
- 单条点击定位详情，多条打开审批中心。处理、拒绝、撤销、到期或锁定后数量减少/清零；打开窗口、查看详情不清零。
- 通知正文只显示数量，不包含服务器、命令、凭证或输出。系统通知中没有批准按钮。

当前跟踪服务在Main每秒读取Core最小ID摘要，等待约1.5秒合并新请求，按ID去重，待审批总数相同但新ID出现仍提醒。对已发现的请求不会因重复轮询、返回前台、重新打开设置而重复发送；不持续催促未处理请求。瞬时请求若在两次采样之间出现且结束，可能不触发通知。

提醒跟随真实待审批集合。旧通知被移除时请求系统关闭；操作已不在当前集合时点击回到审批中心。点击与状态变化竞争时，详情以Core当前状态为准，不能沿用通知批准已失效请求。即使系统仍保留通知，也不会绕过锁定和审批检查。

## 系统限制与验证

Electron当前macOS原生通知使用UNNotification，需要应用签名；未签名包可能返回失败。Dock角标也受系统通知授权影响。通知权限、勿扰/专注模式、声音及横幅样式由操作系统管理，应用不会自动修改。

测试按钮区分系统报告已显示、失败和无法确认，不把调用show()当作横幅已显示。失败只展示固定说明，不显示原始系统错误。当前未签名开发包的macOS原生通知实测返回failed，已经验证界面正确反馈；不能据此声称系统横幅与真实通知点击已通过。正式签名、通知授权后的可见横幅/声音/点击，以及Windows物理桌面外观仍需验收。

已验证的Main点击导航通道与应用内点击使用独立合成数据；通知不自动创建接入或调整规则。代码路径参考：[Electron通知](https://www.electronjs.org/docs/latest/api/notification)、[Dock角标](https://www.electronjs.org/docs/latest/api/dock)、[Windows任务栏](https://www.electronjs.org/docs/latest/tutorial/windows-taskbar)。

## 数据与生命周期

Main在userData的notification-settings.json保存带revision的三个布尔偏好；此文件没有资产或秘密，不需要凭证库解锁。首次使用默认值，损坏配置不自动重新开启提醒；设置页报告存储问题。写入临时文件、同步、替换后更新内存，过期revision拒绝。

去重ID、合并队列及待跳转目标只留在内存。Core摘要不解密命令或读取输出，没有新增MCP工具。Main锁定版本变化、Core不可用、锁定与退出都会清除当前角标、待发送批次及系统提醒；未完成异步读取不能在停止后恢复提醒。应用不会因通知唤醒而解锁或重执行任务。

macOS关闭窗口仍按既有规则锁定，Windows关闭最后窗口仍退出；本批不改后台执行或关闭行为。系统剪贴板、通知权限和本地审计安全边界保持原规则。
