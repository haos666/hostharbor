# 复用提案与实施优先级

> 后续选择（2026-10-26）：用户已确定优先做加密备份/恢复、SSH 配置导入和单台服务器常用操作。本文 R1–R3 保留为研究建议，暂不实施；当前计划见 [个人工作流](../../personal-workflow-plan.md)。

状态：研究提案，尚未修改产品代码。首批建议最多三项，需在后续实施任务中确定范围。估算表示复杂度，不承诺日历工期。

## R1：审批说明与精确短时批准（优先 1，中等）

**解决的问题**：长命令难读、用户不理解为何转人工、同一诊断步骤反复弹审批。参考 [Kino](projects/kino.md) 的单次/会话按钮与 [ssh-mcp](projects/ssh-mcp.md) 的 TTL/generation，但使用自己的执行与权限模型。

**范围**：

- 结构化呈现目标、cwd、提权身份、实际命令、触发片段/参数、规则来源、策略版本与剩余审批时间；MCP 与 UI 共用原因代码和中英文文案。
- 可选 purpose 字段说明调用意图，来自智能体时标记“智能体说明”，不把它当授权依据；限制长度并走已有加密/脱敏链路。
- 保留“仅本次”；对符合条件的非破坏性人工审批请求，可提供“相同操作短时有效”的显式选项，建议首版固定 10 分钟，不默认启用。
- 精确键至少绑定接入 ID/版本、服务器 ID/配置快照、凭证/提权身份、原始命令、cwd、执行参数、策略版本及相关上下文版本；绝不做前缀或模糊匹配。
- 删除、系统关机/重启、磁盘破坏、自定义拒绝等不因该功能跳过人工或拒绝；仍需按模式明确资格。文件传输保持其独立审批，不纳入首版命令短时批准。
- 同一请求键的重复提交继续返回原操作；短时批准只作用于用户允许的后续同参数新操作，两者不能混淆。

**失效**：到期、手动撤销、接入撤销/删除、Token/授权变更、策略变更、服务器/凭证/应用上下文变化、Core 重启；锁定时按锁定限制设置执行，但不能借锁定扩大权限。

**验收**：相似路径/不同 cwd/不同主机/不同提权均不复用；等候期间改配置失效；过期后再审批；未知结果不重新执行；每次复用保留原批准关联；中英文界面一致。验证纯查询宽松模式原有自动通过不受影响。

**复用方式**：采用思路与独立实现，暂不复制参考缓存类。直接复用前仍须逐文件授权审查。

## R2：策略性质与变体回归测试（优先 2，小至中等）

**解决的问题**：现在主要依赖用户遇到某条命令后补样例，难覆盖拼写、包装和组合差异。参考 [ssh-mcp 的性质测试](projects/ssh-mcp.md)。

**范围**：

- 在现有辅助/宽松引擎上补测试，不引入第二套生产分类器，也不为了让测试通过调整已确认的用户模式语义。
- 宽松模式：已知破坏性片段被包进复合/已支持包装形式后，不能因简单改写而自动通过；引号中的字面风险词不能单独触发误报。
- 辅助模式：重建的执行计划不因空白/合法 quoting 改变目标；未支持或歧义结构保留审批；不能把全体 Shell 声称为只读。
- 通用：解析长度/深度/段数上限、确定性、不能异常退出；审批绑定字段变化不能复用；传输进度不得倒退到错误阶段。
- 可选引入 fast-check，先审查其固定版本与许可证；用我们自己的合成生成器，不复制 GPL 测试代码。固定 CI seed + 本地扩展种子，发现问题先在本地留存和评估，再进入公开日志。

**验收**：可复现的反例、快照化故障样例、正常命令不被测试驱动成全人工；控制运行成本；`npm run check` 与相关原生 fixture 通过。不能拿通过的随机样本数当安全证明。

**复用方式**：测试方法；可能增加单一测试依赖，不复制三千行分类器。

## R3：可选活动预算与重复操作提醒（优先 3，中等）

**解决的问题**：权限允许不代表智能体应无限重复；现有并发限制不能阻止低速持续请求。参考 Kino 小时预算与 ssh-mcp profile 滑动窗口。

**范围**：

- 按认证后的接入 ID 和服务器计量，不使用智能体自报名称作身份；可选总调用预算、变更类预算与重复命令提醒。
- 初版不默认增加人工审批；迁移保持现有宽松行为。用户显式开启后，额度耗尽暂停新执行并显示准确原因和恢复时间，不自动弹出大量批准请求。
- get_operation/read_output 等必要结果查询不消耗执行额度；幂等重复请求不重复扣款；拒绝重试不推动解封时间。
- 扣额与派发状态协调，避免持久化失败仍执行；明确失败发生于派发前/后分别如何记账。账本跨 Core 重启保留，失败按所配置限制处理，不悄悄重置。
- 需要加密存储的命令指纹/摘要沿用现有方案，不为计量额外记录秘密。

**验收**：接入之间不串额、并发不超扣、滑动窗口边界、重启不清额度、撤销后查询仍按归属校验；重复提醒不触发命令自动重跑。

**复用方式**：设计思路，使用我们已有 SQLite/事件模型；不直接复制内存 Map 配额模块。

## 后续候选

| 候选 | 来源 | 为什么暂缓 / 下一验证 |
| --- | --- | --- |
| 受管文本变更：diff、备份、版本重检、写后验证、明确恢复 | adremote + Kino | 价值高，但会新增远端变更工具；需权限/敏感 diff/并发/磁盘额度设计，不能等同任意命令回滚 |
| 标签/分组、全局检索、当前服务器动作入口 | Termix | 资产增多后收益更大；先独立设计数据与 MCP 筛选契约，不把选中一个组当全组执行授权 |
| SFTP 扩展兼容与发布竞态测试 | ssh-mcp | 我们已有无覆盖意图；需用不同服务器验证协议实现，未实测前不认定当前普通 rename 已有覆盖漏洞，也不能照搬“改成 overwrite=true”提示 |
| 远端哈希加速可选验证 | 传输痛点延伸 | 本轮 adremote 并非服务器侧哈希；需固定算法/受控调用/能力探测和输出验证，缺少能力时不能悄悄降级为已完整校验 |
| 仅在派发前重试 SSH channel open | ssh-mcp | 需真实 Dropbear/连接故障复现；已经发出命令的未知结果永不自动重跑 |

## 不采用

- 整体迁移第三方分类器、靠命令名白名单保证只读、把 AI 建议当自动授权。
- 暴露可以代表用户批准自己的 MCP 工具、超时自动放行、隐藏恢复授权。
- 新建第二份 MCP 解密凭证库、为复用改写 Electron/Core 边界。
- 将整段结束输出当有时序加密回放、未经授权复制 GPL 源码或无完整许可材料的代码。
- 为追齐同类功能增加云同步、完整插件平台或持久多机 Shell。
