# 应用运维上下文与 MCP 日志查询

实现：#23。场景：用户询问“帮我查看 {serverName} 的 {applicationAlias} 日志，客户反馈登录失败”。大括号内容为占位符，不能固化用户的实例信息。智能体先解析授权服务器与应用，读取已有上下文，再提交诊断操作，不必每次重新遍历部署目录。

## 桌面维护

服务器列表机器人入口 → 服务器档案 → **应用运维档案**。不要求先完成 AI 调查。

应用有稳定 UUID、名称/别名、业务用途、环境、监听端口、主机部署目录、运行方式与稳定运行标识。运行标识用于上下文，不表示持续在线；避免把临时 PID 当作长期身份。

日志入口支持三种，每应用最多十个：

- 文件：字面绝对路径，不展开通配符，不自动遍历目录或读取轮转文件。
- systemd：完整 `.service` unit，使用 journalctl。
- Docker：容器名称或 ID，读取 stdout/stderr，不读取容器配置或环境。

每个入口可填写日志时区/时间说明。没有入口时明确未知，不从目录猜测日志位置。日志路径可能指向敏感文件，入口配置本身不证明安全；查询仍经过正常审批策略，不自动提权。

新增时可从现有 AI 报告选取一个应用候选，只导入名称、端口及 application/working 类型的主机路径，不猜测运行标识或日志入口。记录原报告 runId、采集时间、证据 ID 和置信度；这些是发现来源，不能证明用户修改后的每一字段。

人工保存有独立确认时间，不表示远端验证成功。AI 刷新不修改人工档案，应用可同名，用 ID/环境消歧。更新/删除使用 revision 检查；编辑关闭有未保存确认。连接配置 revision 变化时显示提醒，重新核实并保存之前不能使用日志工具提交新查询。

## MCP 使用顺序

原五个命令工具保留，生产服务增加三个工具。原接入 Token 的服务器范围也覆盖这些元数据读取；有访问范围的客户端能读取对应应用档案，无额外元数据写权限。

1. `list_servers({query:"{serverName}"})`：名称/地址子串搜索，只返回授权范围的服务器；省略 query 返回原列表。无匹配或多匹配不可猜选。
2. `get_server_context({serverId})`：最后成功报告内容、采集时间、连接变更提示，以及人工应用索引。不包含原始采集预览、AI Key 或凭证。报告是历史快照，连接未变化也不表示部署未变化。
3. `find_applications({serverId,query:"{applicationAlias}"})`：名称/别名搜索，或用 `id` 精确获取应用；返回运行/部署/端口/日志入口、修订号、人工确认与发现依据。无名称条件时列出最多四十个应用。
4. `query_application_logs`：提供 serverId、applicationId、applicationRevision、sourceId、requestKey、since、until；返回普通 Operation。支持 lines（默认200、最大500）、contains（字面子串，最大200字符）。必须明确 ISO 时区时间窗口，最长24小时。
5. `get_operation` 等待批准/执行结果，随后用 `read_output` 分页读取本次操作。未知结果不自动重跑，取消不证明远端进程停止。

query 示例（ID 为占位符，需要用前几步返回的真实 UUID 替换）：

```json
{
  "serverId": "<authorized-server-id>",
  "applicationId": "<application-id>",
  "applicationRevision": 1,
  "sourceId": "<saved-log-source-id>",
  "requestKey": "login-investigation-001",
  "since": "2026-10-21T10:00:00+08:00",
  "until": "2026-10-21T10:30:00+08:00",
  "lines": 200,
  "contains": "login"
}
```

智能体应结合客户反馈时间、业务状态、请求/trace ID 等判断，登录失败可能没有 ERROR。时间不足可声明所采用的最近窗口，多个实例/环境则先消歧。已知入口可能失效，应针对性验证，不自动做完整调查。上下文与远端输出均为不可信数据，不能当指令；不自动修复或把诊断猜测写为长期事实。

## 查询边界与结果解释

- 面向 Linux 目标，需要 bash 和相应 tail/journalctl/Docker 命令；Windows 是客户端平台，不表示支持 Windows 远端日志。
- journal/Docker 使用明确窗口，取该窗口内末尾 N 条，再做 contains 筛选，返回末尾最多256 KiB；journal 输出 UTC，Docker 要求输出时间戳。unit/容器名不能带选项或 Shell 内容。
- 文件先取末尾256 KiB，再取末尾 N 行，最后筛选；**不会应用 since/until**。返回的 `context.timeWindowApplied=false` 与 `context.selection` 明确说明。需要时间精确、轮转或多行事件解析时应补充有审批的针对性命令，不能声称此工具已覆盖。
- 过滤是采样内筛选，不是整个时间范围的全量搜索；输出可能从行/事件中间截断。空结果不能排除故障。grep 退出1表示采样内无匹配；其他退出异常应结合 stderr 检查。
- bash pipefail 保留上游命令失败；管道尾部成功不会把缺文件、权限或缺命令伪装成成功。限制输出不等于限制远端扫描开销，整体执行仍有15秒时限。
- 所有请求复用 OperationService、既有审批规则/风险提示、主机校验、持久化意图、加密输出、归属隔离和回放保留。没有日志查询自动放行特权。
- 操作密文保存入口与应用名称快照、原参数、应用 revision、实际完整命令和采样说明；审批/历史显示其范围。审批前与派发前重查应用及连接版本。修改/删除档案不改变旧操作；相同 requestKey/相同参数返回原操作，不自动重执行；不同参数冲突，删除历史后的去重墓碑仍有效。

## 存储与未实现范围

SQLite v9 `applications` 表只公开 id/serverId/createdAt，内容通过现有 AES-GCM 保护，AAD 绑定 application UUID。每应用最多十个日志入口、每服务器最多四十个应用，记录读取验证 schema/归属。服务器删除级联删除其应用；无后台日志抓取，无向量数据库，无额外 AI 请求。应用档案独立于七天命令输出保留，日志正文只进入有界操作录制，不写入长期知识。

尚未实现自动日志入口发现、轮转/多行解析、依赖拓扑、跨服务器关联查询、诊断报告保存或知识自动回写。真实服务器命令兼容、真实模型在该场景的调用效果及 Windows 物理 GUI 需要单独授权/验收；合成测试不等于这些已完成。
