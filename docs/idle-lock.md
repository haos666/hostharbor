# 空闲自动锁定与侧栏

系统设置固定在侧栏左下方，Logo下方直接进入主菜单，不显示锁定图标。侧栏菜单可独立滚动，底部设置保持可见；需要主动锁定时可使用菜单栏/托盘入口。

在系统设置 → 安全 → 空闲自动锁定中，只有30秒、30分钟、关闭三个选项，默认30分钟。选择后立即保存，显示成功或失败；加载失败/版本冲突可重新加载，不能把尚未保存的选择当作成功。读取不含秘密的设置不要求解锁，修改必须处于已解锁状态。

计时按电脑无键鼠活动的系统空闲秒数，使用Main中的Electron powerMonitor.getSystemIdleTime采样，每秒检查，不依赖renderer是否显示、哪个页面或后台计时器。MCP请求、模型返回、SSH输出不会续期；在其他应用使用键盘鼠标也属于电脑活动。

解锁或修改时限后至少给予一个完整时限，再按系统空闲时间判断；用单调时钟计算宽限，调整系统日期不会延长。关闭仅关闭空闲锁定，启动仍默认锁定，系统锁屏、睡眠、关闭窗口及主动锁定行为保留。锁定经过SecurityService/Core路径；默认中止待审批并断开活动连接。若关闭“锁定时暂停 MCP 访问”，仅锁定界面，后台授权访问与待审批保留，人工审批需先解锁，详见 [锁定设置](mcp-lock.md)。断开不代表远端进程停止，不自动重跑。

Main本地idle-lock-settings.json只含revision和seconds，不含资产或秘密；严格三值校验、大小限制、原子替换与revision冲突检查。设置损坏或系统采样失败会请求锁定，不静默当作关闭。锁定失败会在下一轮继续尝试；Core不可用时既有执行接口也会拒绝访问。该本机偏好文件不抵御同用户恶意篡改。

本轮验证包含阈值、活动与后台任务区别、解锁宽限、关闭及更改时限、并发轮询、迟到结果、锁定竞争、损坏文件与失败重试。macOS原生验证真实系统采样可用，并注入时间/空闲样本触发实际utility Core锁定；这不等于物理等待30秒无键鼠活动的端到端验收。Windows物理桌面与真实OS锁屏事件仍需对应环境验证。
