# AI 服务器档案（首版）

在服务器列表点击机器人图标，打开档案窗口。图标有工具提示和无障碍名称。首次没有档案时显示采集范围；已有档案时直接展示已保存结果，不自动联网。

## 使用流程

1. 在系统设置保存 AI 接入，选择支持工具调用的实际模型 ID。OpenAI 走 Chat Completions，Anthropic 走 Messages；只有 Responses 的接口暂不支持。模型显示名称不一定等于 ID。
2. 绑定服务器凭证，先用连接测试核对目标及跳板主机指纹。
3. 打开机器人入口，点击开始/重新调查，核对 AI 地址、模型和采集范围，再确认本次数据发送。
4. 基础查询采集 Linux 系统、CPU、内存、磁盘、运行进程名称、服务、监听端口和容器。AI 根据线索选择后续查询，工具限定为特定进程可执行文件/cwd、systemd 指定元数据、容器指定挂载/端口信息、一级子目录。
5. 全部查询通过统一 OperationService，适用现有策略；全部审批模式下逐条批准。窗口内展示完整命令、目录、目标、路由及凭证版本，可批准或拒绝。拒绝、暂停导致拒绝、未知执行结果均停止本次调查，不自动换命令绕过。
6. AI 调用结构化报告工具，Core 校验结构与成功证据引用后保存。卡片显示系统/CPU/内存/运行时间，表格显示磁盘，应用卡片显示类型、状态、端口及不同用途的目录，单独列待确认项。证据可点开查看本机预览和操作记录 ID。

## 范围与限制

- 首版支持 Linux。不是全盘资产扫描；受当前账号、命令安装情况、采集行数/大小影响。缺失不表示不存在，可能漏掉停止的服务、其他容器引擎、用户自定义部署或需要提权的信息。
- 不提供模型任意 Shell、不安装、不提权，不读取环境变量、进程参数、业务文件、完整配置或日志。固定查询也仍是远端命令，不宣称任意 Shell 是只读的。
- 桌面创建仅该服务器、最长十分钟的内部授权，不生成可用 MCP Token；MCP 认证明确拒绝内部来源，结束撤销，重启撤销旧授权。用户原接入不被扩权。
- 全应用同时一项调查；最多十条不同查询、七次模型请求、十分钟。单条命令十五秒、连接十二秒、模型响应六十秒。基础/跟进预览每项最多 12,000 字符，整次最多 64,000；模型请求 512 KiB，响应 1 MiB。不会无限重试或恢复执行。
- 关闭档案窗口后继续；停止、锁定、连接/凭证变更、AI 配置变更会中止，重启不自动重跑。停止断开连接，不证明远端进程终止。
- 采集结果会发送到本次确认的 AI 地址，可能产生服务费用；不发送 SSH 密码/私钥。已知秘密过滤和常见 Token 脱敏为尽力而为，不承诺服务器任意输出都不会包含敏感信息。服务器内容一律不可信，提示词不能授予权限。
- “有证据”仅表示模型引用了成功采集的记录，不是程序证明结论正确。推测、未知单独标注，关键判断需要人核对。目录区分应用/工作/数据/容器内/主机挂载。

## 保存与清理

SQLite v8 `server_dossiers` 按服务器保存当前调查和最后一份成功档案，整体加密，AAD 绑定服务器 ID。刷新失败保留上一份成功结果；连接依赖/指纹快照变化标记需更新。删除服务器级联删除其档案，操作日志遵循原规则。

档案中的证据预览随档案保留，不受七天命令回放清理影响；完整命令输出仍适用原七天/配额规则。重新调查成功替换旧档案，当前没有多版本档案比较或导出。锁定隐藏，不自动恢复调查。

协议参考：[OpenAI function calling（含 Chat Completions）](https://developers.openai.com/api/docs/guides/function-calling)、[Anthropic tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)。当前不支持流式对话、自动修复、定时调查、Windows 远端或任意 MCP 工具扩展。

## AI 整理失败与恢复（#22）

两条基础查询成功不等于档案生成成功。界面分别报告输出被截断、未调用工具、协议格式、报告字段、证据引用错误；旧版通用错误无法还原当时具体是哪一步失败，不据此判定模型不支持。

- MiniMax-M3.1-Flash 使用低思考强度执行有限信息整理，保留完整 Anthropic assistant 内容用于后续轮次，包括 thinking/signature/text/tool_use。思考内容只在 Core 的有界会话中回传给同一配置服务，不显示、不写入档案或日志。
- 输出截断或模型只返回文字时，最多两次修正机会，切换为紧凑报告；报告字段/证据错误也使用同一两次修正预算。修正只允许报告工具，不允许新查询，总七次模型请求/十分钟上限不变。
- 最终仍失败时保留基础采集，显示“基础采集已完成，AI 整理尚未完成”。点击“整理已有采集”并确认同一/当前 AI 目的地址，只发送已存预览，不连接 SSH、不产生新命令；生成档案沿用原采集时间。支持当前连接版本下的保留采集，已有成功报告仍按原规则保护。
- 系统设置的“测试模型能力”使用已保存当前配置和固定合成样例，验证两轮工具调用与报告结构；不访问任何真实服务器，不修改配置，可能产生少量模型费用。它与模型列表连接测试不同。

兼容依据：[MiniMax Anthropic SDK 官方文档](https://platform.minimax.cn/docs/api-reference/text-anthropic-api) 说明 M3.1 Flash 默认最高思考强度、思考计入 max_tokens，工具多轮必须保留完整 assistant 内容。此次真实 MiniMax-M3.1-Flash 合成两轮测试成功，不能把它等同于真实资产完整调查验收。

已有成功档案也可点击“验证基础整理”：仅将其中的 overview/runtimes 两项基础预览发送给确认的 AI 地址，验证模型生成报告和证据校验；不发送后续查询预览，不执行 SSH，成功后保留原完整档案，显示验证通过状态。它与设置页的合成能力测试不同，包含真实基础采集信息，必须明确确认目的地址与发送范围。

## 编辑与人工修正

档案顶部“编辑档案”打开独立结构化表单，可修改概述、系统/CPU/内存/运行时间、磁盘、应用/端口/目录和待确认项。展示页基础信息为统一字段列表，不再用四张大号文字卡片。关闭编辑遇到未保存内容会确认；保存只更新本机，不执行服务器命令或调用模型。

人工修正独立加密保存，显示“人工修正”及更新时间，不沿用原机器证据。AI 刷新后仍保留修正，其他字段读取新报告。概述及四个基础字段各自独立；磁盘、部署应用、待确认项一旦修改，其整个分区由人工维护，刷新不会逐行合并，避免把旧数组下标套到新发现对象。原报告和采集证据保持原样。MCP 的 get_server_context 返回有效内容、manualFields 和 manuallyUpdatedAt，不把人工值伪装成实时采集。

编辑部署应用只修正本报告描述，不改变下方独立“应用运维档案”中的稳定 ID、日志入口或执行配置。需要修改日志查询入口时，仍使用对应应用的铅笔按钮。版本已变化时需重新打开编辑，正在调查时暂时不能编辑。没有全量修改历史或一键恢复功能；请勿把凭证、Token 或配置秘密写进档案。

部署应用卡片的目录列表默认折叠，点击“目录 · N 项”或聚焦后按空格/Enter 展开、收起。名称、类型/状态、端口和卡片顶部证据始终显示；展开后的目录证据按钮保持独立可用。折叠只影响展示，不更改保存内容或 MCP 返回。
